> 日期：2026-11-05 · 测试：**106/106 通过**（98 既有 + 8 项 P1 审计）；SGLang 0 修改；V1a 不变

## 0. P0：效率统计口径（已修正并全量应用）

| 指标 | 定义 | 说明 |
|---|---|---|
| **Fixed Pool Efficiency**（主指标） | Useful BW ÷ (8 × 单 WIN 标定) | 分母固定 1600/800/80（seq/rand/write） |
| Active WIN Efficiency | Useful BW ÷ (活跃 WIN 数 × 标定) | 仅用于解释内部使用 |
| WIN Utilization | Layer A：服务时长和÷span；Layer B：通道数据通路占用 | 修正了"含排队时间"的统计 bug |
| Load Balance | 全 8 WIN 字节 min/max | 1.0=完全均衡，0=集中 |
| Interface Delivered / Rated | 接口忙碌窗口内交付字节率 ÷ 标定 | 含受限 I/O 占比 |
| 混合读写 | **读写分别报告，不构造单一分母** | 按用户要求 |
| 饱和判定 | 闭环 QD（恰 QD 个在飞，完成一个补一个）+ 完成字节÷仿真窗 | 低需求利用率另行统计 |

**P1 时序审计发现并修复 3 个真实 bug**（全部有测试锁定）：
1. **Layer B 媒体门 bug**（最重要）：`media_start = max(arrival, cursor)` 把同一 WIN 内跨 I/O 的通道并行**串行化**了——Layer B 的 PageSim 本应内部处理争用。修复后 QD 才真正填通道（4KB：QD1 0.1% → QD64 5.1%）
2. 效率过滤键错配（`"seq"` vs `"sequential"`）导致读效率恒 0
3. 利用率误含排队时间（burst 下 >100%）

P1 八项核查全部通过：延迟下限精确（5/7.5/10μs）、小 I/O 延迟受限、**Layer A 无 WIN 内并行（QD 只跨 WIN 生效）**、Layer B 显式页/通道/Plane 映射、三模式独立约束、媒体×接口取 max 无重复计费、跨批游标（含接口）保留、完成字节口径。

### 效率 = min(1, I/O 字节 ÷ (标定 BW × 读延迟)) —— QD 无关（Layer A 无 WIN 内并行）

| I/O | seq(200) | rand(100) | write(10) | 说明 |
|---|---|---|---|---|
| 4KB | 0.3% | 0.5% | 0.4% | 延迟下限主导 |
| 64KB | 4.4% | 8.7% | 6.6% | |
| 256KB | 17.5% | 34.9% | 26.2% | |
| 1MB | **69.9%** | 100% | 100% | seq 仍延迟受限 |
| ≥4MB | 100% | 100% | 100% | 带宽受限 |

**80% 工作点（QD=1）**：读延迟决定阈值——lat 5μs → **I/O ≥ 0.80MB**；7.5μs → **≥1.20MB**；10μs → **≥1.60MB**（= 200GB/s × lat × 0.8）。写：100μs×10GB/s×0.8 → ≥0.8MB。随机读 0.6MB。
**Layer B（假设几何）**：上限 25.6%（51.2/200 结构性差距——几何未知，不调参）；大 I/O 达此上限，小 I/O 靠 QD 填通道（16KB：QD1 0.4% → QD64 20.6%）。

## 2. P3：8-WIN 池扩展与负载均衡

| 放置 | 活跃 WIN | 聚合读 | Fixed Eff | Active Eff |
|---|---|---|---|---|
| balanced | 1/2/4/8 | 200/400/800/**1600** | 12.5/25/50/**100%** | 全部 100% |
| hotspot@win0 | 任意 | **200（钉死）** | **12.5%** | 100% |

- **带宽守恒 ✓**：线性扩展，无超售（P3 断言 + 单 WIN 不超标定）
- **80% 聚合目标全部达成**（balanced + 8 活跃 + QD≥8 + 无接口约束）：seq **1600**≥1280 ✅、rand **800**≥640 ✅、write **80**≥64 ✅（实际 100%）
- 热点集中使 Fixed Eff 钉死在 12.5%（单 WIN 上限），与活跃数无关——**放置是池化效率的第一杠杆**
- Page Striping 解析上界：单个 ≥16MB 逻辑 I/O 条带化 → 1600GB/s（100%）；38.9MB → 24.3μs。未作为放置策略仿真（上界参考）

## 3. P4：UB 接口假设敏感性（核心结论）

| 接口假设 | R100 读吞吐 | 读 FixedEff | 理论上界 | 结论 |
|---|---|---|---|---|
| 无接口 | 1600 | 100% | 1600 | 媒体受限 |
| 封装共享 112GB/s | **112** | **7.0%** | 112 | **80% 数学上不可行** |
| 每 WIN 112GB/s | 896 | 56.0% | 896 | **80% 不可行**（896<1280） |
| 封装共享 896GB/s | 896 | 56.0% | 896 | 同上 |

**不可行结论（数学上界）**：任何 112GB/s 级接口解读下，读侧 80%（1280GB/s）**不可达**——上界 112 或 896GB/s。80% 需要接口聚合带宽 ≥1280GB/s（即每 WIN ≥160GB/s 或共享 ≥1280）。**必须回询硬件方确认 UB×4@224G 语义，这是 80% 结论的第一决定因素。**

写侧：80GB/s 全场景达成（写媒体 10/WIN 是瓶颈，接口 ≥80 不约束）——写 80% 目标（64）对接口不敏感 ✅。

混合 R50W50：读 39.9 / 写 40 GB/s——读写共享 WIN + 写 20× 慢于读，**读吞吐塌到 2.5%**（写主导时间窗）。写入突发+并发恢复：restore 延迟 0.19ms（无接口/每WIN112/共享896）→ **2.44ms（共享 112，接口头阻塞）**。

## 4. P5：损耗归因（同 Trace、同窗口、基础链+分支）

### KV Trace（48 I/Os = 32 读 + 16 写 × 38.9MB）

| 层级 | span | 读 GB/s | 写 GB/s | 归因 |
|---|---|---|---|---|
| C0 解析理想（work-conserving） | 8.58ms | — | — | 下界 |
| C1 burst 均衡（装箱损耗） | 8.58ms | 145.1 | 72.8 | **装箱损耗 = 0** |
| C2 闭环 QD=8（槽位耦合） | 15.79ms | 78.8 | 39.5 | **+84% span：慢写占并发槽，读派发饿死** |
| C2a +热点@win0 | 68.6ms | 18.1 | 9.1 | **放置损失 8×** |
| C2b +共享接口 112 | 17.80ms | 69.9 | 35.1 | 接口叠加 +13% |

- **读写竞争（成对实验）**：读钉在写的 WIN → restore 4.29ms vs 钉在空闲 WIN 0.19ms——**头阻塞 22×**
- 小 I/O Trace：C0=C1=C2 = 69.9GB/s（4.4%）——**固定延迟是唯一主导损耗**（−95.6pp）；热点再 8×；接口无影响
- **Layer B 开关**（假设几何）：通道数据通路是绑定资源（Δ −2.95/3.05ms）；页延迟 −0.01ms；Plane 争用 0
- **Unknown（不赋值）**：FTL、ECC、GC、读干扰、写放大、P/E 寿命效应

## 6. 80% 达成条件汇总（交付物 3）

| 目标 | 达成条件 | 不可行条件 |
