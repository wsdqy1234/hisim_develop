## P0：接口影响是否被 DRAM 共载掩盖——**否，原解释撤回**

### 1. 用户算术确认

p3e 实测：p4k +3.9ms、p16k +15.6ms；理论 `bytes×(1/112−1/1600)`：4.19−0.29=3.9ms、16.79−1.17=15.6ms。**接口差值 1:1 全额传导**，未被掩盖。

### 2. 真实机制（golden 数据 + 批级证据）

两个 reuse 在本离线仿真流中**总是分属独立 bs=1 批次**（实测：同时间戳也如此——释放/合批时序决定；5D p3e 的 p16k 亦然，2×16392>MAXT 32768 仅差 16 token 是次要因素）：

| Regime | 证据（16K golden，确定性顺序） | 接口差值去向 |
|---|---|---|
| **A. 串行批 + 无 L3 屏障**（ser：MAXT 32768） | none [270.2, 450.1] → s112 [285.8, 465.7]：**两请求均 +15.6ms** | **全额传导**：HBF 请求自身加载 1.18→16.8ms；其后继批（DRAM 请求）等待时间同步 +15.6 |
| **B. 串行批 + L3 写屏障**（golden "co"：host 更大） | none/s112 批时钟**完全相同** 7235.881ms：load 1183.6μs+l3_ovf 231346.7μs ≡ load 16792.6μs+l3_ovf 215737.7μs（和恒为 L3 写 235ms=1.88GB/8GB/s） | **被 L3 写屏障吸收**（屏障 231/215.7ms 与 load 精确互补，批时长=max(load+infer, l3_backup)） |
| **C. 真合批 max() 吸收**（理论） | 不可构造：同时间戳仍 bs=1 分批 | 理论域：合批时 load=max(ΣL2,ΣHBF)=138.3ms，接口差值 ≤16.8ms 全吸收 |

**原报告（5E.1 §3.3）"DRAM 共载并行吸收（≤3.5%）"解释撤回**。修正表述：
1. p3e 的 +15.6ms 是**全额传导**（Regime A）；"3.5%"只是相对值（15.6/450），并非"被吸收"；
2. p95 请求身份在 p3e 两 run 间**翻转**（heap salt 平局随机决定批序：unlimited=DRAM 先、s112=HBF 先）——p95 对比混入了不同请求的关键路径；
3. golden（确定性顺序）下 Regime A/B/C 三种去向均已实证并存档。

### 3. Host Load 合成语义（P0 问 4）

`batch load = max( max_per_request(L2 durations), max_per_request(HBF durations) )`：
- 每介质每轮累加器 = **max**（Phase 3E "轮内并行事件"语义，state.py 实测锁定 T1）
- 同介质并发加载经**共享资源游标串行**：第 2 个请求时长含排队等待 → 轮 max = 串行 makespan（n2_A 5743μs=2×2871 机制，T2 锁定）
- 跨介质 = max（T4 锁定）——**无重复计费**；相位（load→infer→backup）串行为保守建模选择（barrier 模式），已文档化

### 4. 时间账本（16K golden，P0 问 5/6 的 p95 关键路径）

以 `p16k_str_ser_s112`（p95=465.7 = rid …DRAM 请求，第二批）为例（ledger.json 可逐项复查）：

```
build 阶段: 3×(infer 83.2ms + backup 23.5ms striped) + 8×decode 1.56ms   [时钟至 ~2.4s]
reuse 波 (t=7.0 起，两个 bs=1 批):
  批1 (HBF 请求): load=16792.6μs [HBF 条带 1.17ms + 接口 16.8ms 并行 max] + infer 2.35ms
                  → TTFT₁ = 285.8ms（= 自身 load+infer+decode+base）
  批2 (DRAM 请求): 等待批1完成 287.7ms + load=138305.1μs [38.88MB×... 1.88GB/13.6GB/s]
                  + infer 2.35 + decode ≈ 8×1.6ms
                  → TTFT₂ = 465.7ms = p95（关键路径 = 批1 时长 + DRAM 加载 138.3ms）
```
不可重叠项未相加：HBF media 与 interface 并行（win 池 max 语义）；同批跨介质 max；批间串行为真实依赖。

n2 账本：A 批 load=5743.1（2×DRAM 串行 makespan）+infer 1630 → TTFT 7.40ms；str 批 load=2874.9（max(DRAM 2865, HBF 24)）→ 4.50ms。
p4k 账本：批1 l3_ovf 22380.9μs + load 34580μs → 59.7ms；批2 DRAM 34.6ms → 123.5ms。

## P1：N=2 / N=4 口径统一

### N=2（7.40ms vs 4.50ms 之谜）——**已定案**

| 差异项 | 5D n2_A（7.40） | p3e n2_A（4.50） |
|---|---|---|
| `HISIM_SHARED_DRAM` | **=1**（5D 驱动全场景导出） | **未导出**（p3e 驱动仅 B70 分支导出——**驱动脚本 bug**） |
| 批结构 | bs=2（两 reuse 合批） | bs=2（相同） |
| load | 5743.1μs（共享 DRAM 串行 makespan） | 2865.4μs（独立模型无竞争） |
| config | config_hbf_l3.json | config.json（实测证明无关：两 config 均 4.5/4.5 ×2 复现） |

**结论**：p3e 的 A 基线因漏配 `HISIM_SHARED_DRAM=1` 而**偏快**，5E.1 §3.2 的配对改善率被高估。golden 协议（全场景 SHARED_DRAM、确定性顺序、Case ID+config hash）下 n2_A=7.40ms 复现 ✓。

### N=4：A/B 两类对照分离（不混谈）

- **A 类（真实系统级，V1a 放置，允许不同命中）**：n4_A 46.1ms（3 命中 1017tk） vs n4_str 34.7ms（命中 678tk）→ **−24.7%**——评价 V1a 实际策略（含分池驻留差异）
- **B 类（介质隔离，同请求/同命中集/同恢复量）**：16K 全量恢复对 A vs HBFO（各 32766tk 完全相等）：p95 419.6 → 282.5ms（**−32.7%**）；4K：123.5 vs 59.7+…；n2 同（4.5 vs 7.4）——隔离 HBF 媒体/接口时序收益
- **B70 混合放置（V0 70/30）**：p4k/p16k 均 **0%**（golden，确定性）：第一轮被 L3 写屏障门控（235.9ms 不变），第二轮由 DRAM 侧请求设定 p95（419.6ms 不变）——**混合放置的加载收益被 L3 写屏障增长精确抵消**（231.3 vs 94.2ms 屏障差 ≈ 137ms 加载差）

## P3：接口与 80% 媒体效率最小对照（全部 Hypothesis）

### 16K HBFO（全 HBF 命中，介质隔离域）接口曲线

| 接口假设 | p95 (ms) | Δ vs 无限制 | HBF 加载理论 |
|---|---|---|---|
| 无限制 | 282.5 | — | 1.88GB/1600=1.17ms |
| 共享 896 | 283.4 | +0.9ms | 2.10ms |
| 共享 1280 | 282.8 | +0.3ms | 1.47ms |
| 共享 1600 | 282.5 | 0 | 1.17ms |
| **共享 112** | **298.1** | **+15.6ms（1:1）** | 16.79ms |

- 接口敏感性只在 **<896GB/s 聚合**时进入 TTFT（≥896 差值 ≤0.9ms 被 L3 屏障/DRAM 路径掩盖）
- B70 混合域：所有接口/媒体/随机变体 p95 恒 419.6ms（Regime B 吸收）——**混合域的接口结论须标注"被 L3 写屏障掩盖"**

| 变体 | B70 域 p95 | HBFO 域 p95 | 结论 |
|---|---|---|---|
| seq 200（包络） | 419.6 | 282.5 | 基线 |

### 80% 效率结论类型学（P4 要求）

- **自然效率**（实测/校准）→ 未测（Layer B 未校准）
- **条件效率**（人工设 0.8 后的 QoS 响应）→ 本表：对 TTFT 的影响在 HBFO 域 ≤1.8ms（p95 相对 ≤0.6%），B70 域 0——**80% 媒体效率假设对 QoS 几乎无感**（瓶颈在 L3 屏障/DRAM/批结构）
- 分母口径：媒体效率=每 WIN 顺序/随机读 GB/s ÷ 200/100；池化效率=聚 合交付 BW ÷ (8×额定)（5C 定义）
