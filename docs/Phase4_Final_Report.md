## 1. 效率定义（口径统一）

| 指标 | 定义 | 统计边界 |
|---|---|---|
| **Media BW 效率** | 单 I/O：`bytes / media_service_time / media_bw` | 仅 HBF 媒体，不含互连 |
| **Pool 有效 BW** | 一批 I/O：`total_bytes / makespan / media_bw` | 含排队、并发、I/O 间争用 |
| **Interconnect 效率** | `bytes / ic_time / ic_bw` | HBF→HBM 链路 |
| **E2E 效率** | `bytes / max(media, ic) / min(media_bw, ic_bw)` | 端到端（单 I/O） |
| **设备利用率** | Σ通道数据通路忙时间 / (通道数×窗口) | 区别于带宽效率：通道忙 ≠ 满带宽 |

**参考带宽**：51.2 GB/s = 32ch × 1.6GB/s，**模拟参考值**（HBFSim nominal，非硬件实测，未经 MQSim 标定）。

## 2. P1：页级模型审计与效率曲线

### 2.1 模型修复内容

新增 `hbf_page_sim.py`（离散事件）：逻辑 I/O→NAND 页拆分→通道轮转条带（全局页序）→通道内最少忙 Plane 选择→
- **读**：Plane 阵列读（tR=10μs）→通道数据输出（16KB/1.6GB/s=10.24μs），不同 Plane 的阵列读与前一页的通道传输**流水重叠**
- **写**：通道数据输入→Plane 编程（tW=100μs），**尾部编程延迟暴露**（公式的 max() 掩盖了它）
- 通道/Plane 忙游标跨 Batch 保留（与 SharedHbfResourceManager 语义一致）
- 经 `HISIM_HBF_MEDIA_MODEL=pagesim` 接入生产路径，**默认 formula 保证 74 项旧测试不回归**

### 2.2 曲线对比（读，QD=1，nominal）

| I/O | formula（Theory Bound） | **pagesim（Model Behavior）** | 差异原因 |
|---|---|---|---|
| 4KB | 0.8% | **0.4%** | 首页 tR+传输串行（20.24μs） |
| 16KB | 3.2% | **1.6%** | 同上 |
| 64KB | 12.8% | **6.3%** | 仅 4/32 通道被使用 |
| 256KB | 51.2% | **25.3%** | 初始 tR 暴露 |
| 1MB | 100% | **67.2%** | tR + 2页/通道 |
| 4MB | 100% | **89.1%** | tR 摊薄 |
| 16MB | 100% | **97.0%** | 通道受限 |
| **38.9MB（KV 实际尺寸）** | 100% | **97.6%（读）/ 87.7%（写）** | 写为尾部 tW |

**80% 读阈值：pagesim ≈ 2MB（QD=1）**，不是公式给出的 410KB。写阈值更高（尾部 tW 随页数摊薄）。

### 2.3 QD 是小 I/O 效率的决定因素（模型行为，公式完全缺失）

32×64KB 读，完整模型：**QD=1（closed-loop）6.3% → QD=32（同到达）80.4%**——并发把空闲通道填满。
结论：小 I/O 效率不是介质属性，是 **I/O 粒度 × 并发度** 的联合属性。

### 2.4 审计清单（用户要求的逐项核对）

| 审计项 | formula | pagesim |
|---|---|---|
| 逻辑 I/O→页拆分 | ✔（仅计数） | ✔（逐页事件） |
| 页→Channel/Plane 映射 | ✘ | ✔（通道轮转 + 最少忙 Plane） |
| 不同 Channel 并行与忙状态 | ✘（聚合 BW） | ✔（每通道数据通路口独立游标） |
| Page 延迟与传输组合 | ✘ max() 掩盖 | ✔ 读流水 / 写尾部编程 |
| 小 I/O QD=1 用几个通道 | ✘ | ✔ 4KB→1ch，64KB→4ch（实测 6.3%） |
| 读写混合对吞吐影响 | ✘ | ✔ 写拖尾 tW 串行化编程 |
| 聚合带宽守恒 | ✔ | ✔（4×16MB 并发 = 50.8GB/s ≤ 51.2，无超售） |

## 3. P2：损耗归因（同 Trace 逐机制开关，全部实测）

### 3.1 瀑布测量（新增损耗 = 上一级 − 本级）

| Trace | L1 +通道数据通路 | L2 +页延迟 | L3 +Plane争用 | 最终效率 |
|---|---|---|---|---|
| **KV restore 突发 N=2**（2×38.88MB 并发读） | −0.5% → 99.5% | −0.7% → 98.9% | −0.0% | **98.9%** |
| **KV backup 突发 N=2**（2×38.99MB 并发写） | −0.2% → 99.8% | **−6.2%（尾部 tW）** → 93.7% | −0.0% | **93.7%** |
| 单次 38.9MB 读（KV restore 实际尺寸） | −1.1% | −1.3% | −0.0% | **97.6%** |
| 单次 38.9MB 写（KV backup 实际尺寸） | −0.8% | **−11.5%** | −0.0% | **87.7%** |
| 小 I/O 32×64KB 读（QD=1） | **−87.5%（通道未填满）** | **−49.4%** | −0.0% | **6.3%** |
| Churn 混合（9 备+7 恢复） | −1.0% | −7.3% | −0.0% | **91.8%** |

### 3.2 结论

1. **KV 尺寸（38.9MB）I/O 的媒体损耗 ≈ 1–12%，主要来自写路径尾部 tW**；Plane 争用在 32-Plane 几何下≈0
2. **小 I/O 的损耗主因是通道未填满（−87.5%），其次是页延迟（−49.4%）**——不是"20% 中的 5%"
3. **未建模项 = Unknown，不赋数值**：FTL 映射、ECC、GC、读干扰、写放大、Die-Enable 总线共享（除通道数据通路串行化的近似外）。需 MQSim/硬件标定
4. 第一版报告的 "10%+5%+3%+2%" 分布**作废**，以 3.1 实测表为准

## 4. P3：Workload C/B 与 Resource C/B（分开测算）

### 4.1 定义

- **Workload C/B（需求侧）** = 工作集字节 / 峰值业务带宽需求（Trace 窗口统计，按到达时间分桶=需求密度）
- **Resource C/B（供给侧）** = Host 配置容量 / 配置带宽（**旧报告的 14.7ms = 此项，非工作负载需求**）

### 4.2 N=2 Host Hit 工作负载（工作集 1360tk = 156MB）

## 5. P0：三种"0.8 效率"的独立实验（N=2，Independent 拓扑）

| 组 | Media BW | IC BW | reuse-TTFT P95 | 全请求 TTFT P95 | batch load | 实测 HBF 媒体 BW | 实测 HBF IC BW | **瓶颈** |
|---|---|---|---|---|---|---|---|---|
| A（纯 DRAM） | — | — | 7.4ms | 16.8ms | 5743μs | — | — | DRAM 13.6GB/s |
| B70 nominal | 51.2 | 16.0 | 4.5ms | 5.4ms | 2875μs | 42.2 GB/s | **16.0 GB/s（饱和）** | **互连** |
| **B70 EFF-M** | **40.96** | 16.0 | **4.5ms（与 nominal 完全相同）** | 5.4ms | 2875μs | 34.8 GB/s | 16.0 GB/s | **互连** |
| B70 EFF-I | 51.2 | **12.8** | 4.7ms | 5.6ms | 3040μs | 42.2 GB/s | 12.8 GB/s（饱和） | **互连** |
| B70 EFF-MI | 40.96 | 12.8 | 4.7ms | 5.6ms | 3040μs | 34.8 GB/s | 12.8 GB/s | **互连** |

（C 场景在 N=2 与 B70 数值完全相同——容量无压力。TPOT P95 各组一致 ≈996ms，吞吐一致。）

**结论（P0 核心口径修正）**：
1. **媒体效率 0.8 对本工作负载的 TTFT/load 影响为 0**（4.5ms = 4.5ms）：38.9MB I/O 媒体时间 970μs ≪ IC 2430μs，媒体不是瓶颈
2. **互连效率 0.8 直接决定加载时长**（2875→3040μs，TTFT +4.4%）：实测 HBF IC BW = 配置值（链路饱和），实测媒体 BW < 配置值（未饱和）
3. **第一版把 IC 12.8 的结果（63.5% TTFT）当成"0.8 媒体效率收益"是口径错误**；正确表述：IC 受限时 63.5%，媒体受限时无影响
4. Shared Downstream（13.6）拓扑：B70/C = 16.9ms ≈ A（100.6%），HBF 优势归零（与 Phase 3E-Closure 一致）——HBF+DRAM 在共享下游串行

## 6. P4：80% 媒体效率下的 HBF 收益（含容量压力 Churn）

### 6.1 N=2 Host Hit（无容量压力）

QoS（P95 TTFT ≤ 110% A、TPOT ≤ 110%、吞吐 ≥ 95%）：**全部通过**。
B70（EFF-M）reuse-TTFT = 4.5ms = A 的 **61%**，QoS 余量 49pp。

### 6.2 Churn（Build 9×340tk → Evict → Reuse → 工作集 3060tk，L2+L3 溢出路径）

| 场景 | Host 容量 | 命中率 | HBF/DRAM/Recompute（tk） | 全请求 TTFT P95 | 吞吐 | QoS |
|---|---|---|---|---|---|---|
| A | 2048 | **18.8%** | 0/1152/4968 | 41.8ms | 0.641 | 基线 |
| B70（EFF-M） | 2048（1433+615） | **10.5%** | 256/384/5480 | 37.8ms | 0.642 | **90.4% ✅** |
| B70（nominal） | 2048 | 10.5% | 同上 | 37.8ms | 0.642 | 90.4% ✅ |
| C（EFF-M） | **3481（2048+1433）** | **49.9%** | 1356/1695/3069 | 34.0ms | 0.642 | **81.3% ✅** |
| C（nominal） | 3481 | 49.9% | 同上 | 34.0ms | 0.642 | 81.3% ✅ |

（TPOT P95 各组一致；Shared-DS 组与 Independent 数值一致——churn 的等待被重计算主导。）

**关键事实**：
1. **媒体效率 0.8 在 churn 下同样零影响**（B70_M ≡ B70_nominal，C_M ≡ C_nominal）——再次确认瓶颈在 IC/DRAM 路径与调度
2. **C（扩容）把命中率从 18.8% 提到 49.9%（2.7×）**：工作集 351MB ≤ Host 399MB → 9/9 复用请求完整命中 339/339tk（A/B70 只恢复到 128tk 部分前缀，经 L3 溢出路径）；期末占用 HBF 1426/1433（99.5%）、DRAM 1782/2049
3. **B70 等容量替换在容量压力下命中率低于 A（10.5% vs 18.8%）但 QoS 仍通过（90.4%）**：差异来自池拆分后的 restore/eviction 交互（V1a 有界重试 + MAX-available 语义下的 L3 恢复分配），**不是 HBF 介质速度问题**（HBF 命中的 reuse TTFT 4.9–6.5ms vs DRAM 命中 27–34ms）
4. **不能仅凭 N=2 断言 70% 替换全局最优**——容量压力下 B70 的命中率回归需要 V1b（按访问价值放置）或混合容量策略

### 6.3 容量收益 vs 性能收益的适用边界

| 收益类型 | 条件 | 证据 |
|---|---|---|
| **性能收益**（TTFT） | Independent 拓扑 + IC ≥ 12.8GB/s | N=2：B70 = 61% of A；HBF 命中 reuse 4.9ms vs DRAM 命中 27ms |
| **容量收益**（命中率） | 工作集 > 原 Host 容量，且扩容后 Host ≥ 工作集 | C：18.8%→49.9%，339/339 完整命中 |
| **无收益** | Shared Downstream 13.6GB/s（N=2）；媒体 BW 下降 20% | 实测零影响 |
| **负收益** | 等容量 70% 替换 + 容量压力 + V1a 放置 | 命中率 18.8%→10.5%（QoS 仍过） |

## 9. 五个最终问题的回答（修正版）

**Q1 工作负载需要怎样的容量与峰值带宽，容宽比？**
工作集 N=2=156MB / Churn=351MB；恢复需求峰值（1ms 窗）77.8GB/s、P95（10ms 窗）7.8GB/s、全程平均 <0.1GB/s；**满足 QoS 的最低恢复带宽 6.0GB/s**。Workload C/B：2.0ms（N=2，1ms 窗）/ 4.5ms（C-churn）。Resource C/B（旧 14.7ms）是配置容量 ÷ IC 带宽，与需求无关，两者已分离。

**Q2 不同 I/O Size/QD 下能否达到 80% 标定效率？**
**模型行为口径**：读需 I/O ≥ ~2MB（QD=1）；KV 实际尺寸 38.9MB 读 97.6%、写 87.7%；小 I/O（≤256KB）QD=1 仅 0.4–25%，**但 QD=32 时 64KB 可达 80.4%**（并发填满通道）。公式口径的"410KB 达 80%"为 Theory Bound，作废。

**Q3 达到 80% 时瓶颈是媒体还是互连？**
**互连**。媒体 40.96GB/s（0.8）时 TTFT/load 与 51.2 完全相同（媒体时间 970μs ≪ IC 2430μs）；实测 HBF IC BW=配置值（饱和），媒体 BW < 配置（未饱和）。提升端到端性能应优先提升互连带宽，而非媒体。

**Q4 80% 效率下 70% DRAM 替换是否满足 QoS？**
满足。Independent 拓扑：N=2 reuse-TTFT=61% of 基线（余量 49pp）；Churn 90.4% ✅、吞吐 100.2% ✅。但注意：等容量替换在容量压力下命中率 10.5% vs 基线 18.8%（池拆分 restore 交互，非介质问题）；**Shared Downstream 拓扑无性能优势**（100.6%）。

**Q5 哪些负载适合 HBF，哪些留在 DRAM？**
适合 HBF：大前缀完整恢复（≥2MB I/O、38.9MB 达 97.6%）、并发突发恢复（HBF 命中 4.9ms vs DRAM 命中 27ms）、容量扩展场景（命中率 2.7×）。留在 DRAM/需改进：小 I/O 高频访问（QD=1 时 <6%）、Shared-DS 拓扑下的并发（串行化）、容量压力下 V1a 放置的 restore 路径（V1b 待开发）。
